# R17 (legacy) — Evidence publication failure survives terminal aggregation

**Repository:** ForkbombEu/wallet-conformance-test-fb · **Branch:** `main`
**Base:** `cce2848` (L16, pushed; reviewed pin `519b112` plus later pushed work kept) · **Commit:** this commit (`fix: preserve evidence publication failure through terminal aggregation (R17)`)
**Date:** 2026-10-28 · The newer fork has its own `handoffs/R17.md` and commit.

## Defect reproduced

At the function boundary:
1. `publishRunEvidence` turned `pass` into `inconclusive` when `ArtifactStore.publish` returned limitations.
2. `JobManager.finalize` then ran `withLifecycle`, which re-summarized the completed, all-PASS native data and **restored `pass`** with zero artifacts.

Two more gaps:
- The publisher had no typed outcome: callers could only count human-readable strings.
- An unreadable file was reported as "missing", and a failed copy into storage threw. An exception anywhere in `publish` became an execution `error` that dropped the native data.

## Changes

| File | Change |
|---|---|
| `src/runner-api/artifacts.ts` | `PublishedArtifacts.failed: PublicationFailure[]`, with `{ filename, reason }` and reason one of missing / unreadable / oversize / write_failed / unsafe_name / duplicate. Each declared file is checked individually: ENOENT means missing; any other stat or read error means unreadable, reported by code only (no paths). Over the cap is oversize (cap unchanged at 32 MiB). A failed copy into storage is write_failed, instead of throwing. Adds the named seam `ArtifactStoreOptions.readSource` (tests only; production reads the file system) and `errorCode()`. |
| `src/runner-api/summarize.ts` | `EvidenceCompleteness { unpublishedArtifacts? }` and `applyEvidenceCompleteness`: a native `pass` with unpublished declared evidence becomes `inconclusive`. Nonpass results and native verdicts are untouched. `summarizeResult(execution, native, evidence?)` applies it after the native rules. |
| `src/runner-api/job-manager.ts` | `ExecutionEvidence.unpublishedArtifacts` is internal and never a wire field. `finalize` passes it to `withLifecycle`, which re-summarizes native and lifecycle state together with evidence completeness. Lifecycle recomputation can therefore no longer restore `pass`. |
| `src/runner-api/main.ts` | `publishRunEvidence` derives `unpublishedArtifacts` from the publisher's typed `failed` list, never from limitation text. It applies the rule and adds one explanatory limitation. If `publish` throws, the native data is kept, nothing is advertised, every declared file counts as unpublished, and a code-only limitation is added. `RunnerMainOptions.artifactSourceReader` is a named internal seam (tests only), next to `processAdapter`. |
| `tests/runner-api/publication-aggregation.test.ts` (new) | See below. |

**Unchanged:**
- RunnerResult v1.0 (strict) and the status vocabulary.
- The download integrity behaviour for bytes deleted later (`ARTIFACT_CORRUPT`).
- The production artifact cap.
- An informational limitation (e.g. unknown engine revision) does not downgrade.

  - missing file;
  - `chmod 000` (unreadable / EACCES);
  - sparse file of cap + 1 bytes (oversize);

  A readable sibling still publishes with an exact SHA-256, and no private path leaks.
- **UNIT (aggregation):** typed executors through the real `publishRunEvidence` and `JobManager`. Covers:

## Limitations

- Downgrading on publication failure applies only to a native `pass`. It never invents a native FAIL, and it does not rewrite already stored results when bytes are deleted later.
- Duplicate and unsafe-name declarations count as publication failures. The native worker declares only `native-results.json`, so they cannot occur in production today.
