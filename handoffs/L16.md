# L16 — Legacy suite and unhandled errors can no longer become PASS

**Repository:** ForkbombEu/wallet-conformance-test-fb · **Branch:** `main`
**Base:** `e2e24c6` (reviewed pin `519b112`, plus the pushed second-review fixes `4d1dd7c`/`e2e24c6`, which were kept) · **Commit:** this commit (`fix: account for legacy suite and unhandled errors before reporting PASS (L16)`)
**Date:** 2026-10-28

## What was still wrong at `e2e24c6`

The second-review round (`4d1dd7c`) already let `onTestRunEnd` take Vitest's arguments, made the session INCOMPLETE on suite errors, and had the worker downgrade a non-clean suite to `partial`. Three gaps remained, and the first one still produced a false aggregate PASS through the real server:

1. **`summarize.ts` ignored `native_suite_status`.** `JobManager.withLifecycle` re-summarizes every worker result, so the worker's `partial` downgrade was discarded. Completed, all PASS and INCOMPLETE meant `pass` again. Proven at three levels (see below), including the **compiled server**.
2. **No error details were exported.** The suite errors were counted but not recorded: no `errors` in the native export and no limitation.
3. **Statuses and timestamps:**
   - a zero-test (collection-failure) run was persisted as PASSED in the session DB (the export alone said INCOMPLETE);
   - `reason === "interrupted"` with only passes ended PASSED;
   - `startedAt` was the first assertion's timestamp, not the session start.

## Behaviour notes and limitations

- **Human CLI:** a run that collects zero tests is now recorded as INCOMPLETE in the session DB (it was PASSED), and an interrupted run with only passes is INCOMPLETE. Ordinary FAIL runs are unchanged.
- **The `interrupted` reason:** under `vitest run` it is reached only through bail or a keyboard cancel, and bail implies a failure, so it is handled in code but not reproduced by a dedicated child fixture. A SIGINT/SIGTERM makes Vitest exit without `onTestRunEnd`, which leaves the OPEN export: that path is already covered (cancel/deadline tests keep `partial` evidence).
- **Where error details go:** native error messages live in the raw `native-results.json` artifact and in one bounded limitation. No wire field was added (RunnerResult v1.0 unchanged).
- **Newer fork:** unchanged by this task (it already has the analogous safeguard).
